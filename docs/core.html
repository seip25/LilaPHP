LilaPHP

Configuration & Environment (`backend/.env`)

Settings in backend/.env control the framework's behavior globally. Under our API-first architecture, no monolithic App instantiation is required—all configuration properties are read into static memory upon boot (`_core/bootstrap.php`). 

APP_NAME="LilaPHP API Engine"
APP_ENV="production"
APP_DEBUG=false
APP_URL="http://localhost:8080"
APP_KEY="base64:..." # Generated via: php cli.php key:generate

# Database
DB_PROVIDER="mysql" # or sqlite
DB_HOST="mysql"
DB_PORT=3306
DB_NAME="lilaphp"
DB_USER="root"
DB_PASSWORD="secret"

# High Performance Caching & Queues
CACHE_DRIVER="apcu"      # RAM in-memory cache
DB_CACHE_DRIVER="redis"  # Distributed cache & background workers
REDIS_HOST="redis"
REDIS_PORT=6379

# Logging
LOG_ENABLED=false        # Disabled by default for maximum concurrency

Direct API Execution (Why No `new App()`?)

In previous versions, developers had to instantiate a monolithic object like new App(['security' => ...]) on every single HTTP request. This approach created unnecessary CPU allocation, redundant configuration parsing, and dependency injection overhead.

LilaPHP's API-First Paradigm: When Nginx dispatches a request (`/api/ping`) to `/var/www/html/index.php`, our ultra-lightweight bootstrap (`_core/bootstrap.php`) instantly wires all static helpers (`Response`, `Cache`, `Database`, `Validate`) into shared process memory via OPcache preloading (`preload.php`). Your physical endpoint (`backend/routes/ping.php`) executes immediately without class instantiation wrappers or middleware loops.

index.php -> backend/routes/*.php 
<?php
/** Direct physical execution */
use Core\Response;
use Core\Validate;

// Zero setup or constructor calls needed:
$clean = Validate::assert($_REQUEST, ['email' => 'required|email']);

Response::json(['status' => 'success', 'data' => $clean]);

Core API Components (`_core/`)

LilaPHP provides high-speed static and singleton core utilities tailored specifically for JSON APIs, database pooling, background tasks, and anti-malware security.

`Core\Database` & `Core\Cache`

Database::getInstance() maintains an active, reusable PDO connection pool across requests. Cache delivers dual-tier speed (`Cache::api()` for local APCu RAM, and `Cache::db()` for distributed Redis). 

use Core\Database;
use Core\Cache;
use Core\Response;

// Cached query inside process RAM for 60 seconds
$items = Cache::api('active_items', function() {
    $pdo = Database::getInstance();
    $stmt = $pdo->query("SELECT * FROM items WHERE status = 'active'");
    return $stmt->fetchAll();
}, 60);

Response::json(['items' => $items]);

`Core\Validate` & `Core\Response`

Validate::assert() inspects payload inputs (using $_REQUEST['lang'] for localized error messages) and halts execution instantly on invalid payloads. Response::json() outputs clean JSON with automated CORS and HTTP status headers. 

use Core\Validate;
use Core\Response;

// Validate payload with rules
$data = Validate::assert($_REQUEST, [
    'username' => 'required|min:3',
    'age' => 'required|numeric'
]);

// Return JSON response with HTTP 201 Created
Response::json(['status' => 'created', 'user' => $data], 201);

`Core\Upload` & `Core\Task`

Upload::save() provides anti-malware MIME scanning and blocks embedded PHP scripts. Task::dispatch() pushes long-running jobs to background Redis queues or OS execution threads without slowing down your API endpoints. 

use Core\Upload;
use Core\Task;

// Handle safe file upload
$savedFile = Upload::save($_FILES['document'], null, ['application/pdf' => 'pdf']);

if ($savedFile) {
    // Offload heavy text extraction to background CLI worker
    Task::dispatch('process_pdf_document', ['filename' => $savedFile]);
}
