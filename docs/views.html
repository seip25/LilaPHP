LilaPHP

Frontend Architecture

Lila.js Reactive SPA Engine & Bluebird CSS

LilaPHP eliminates the overhead and complexity of heavy frontend toolchains. Lila.js is a zero-build, ultra-fast reactive SPA micro-engine (< 8 KB) providing declarative templates (html`...`), reactive state proxies, hash client routing, route guards, event delegation, and built-in UI components (Toasts, Modals, Theme Switcher).

1. Zero-Build Architecture (KISS Philosophy)

In traditional modern web stacks, creating a reactive Single Page Application requires Node.js, Webpack/Vite, Babel, npm dependencies, and minutes of bundling. In LilaPHP, the frontend is 100% decoupled static files:

  • Zero Build Steps: Edit frontend/index.html, save, and refresh your browser. Everything runs natively via modern JavaScript ES6+ standards.
  • High-Speed Nginx Static Delivery: Nginx serves static HTML/CSS/JS with zero PHP-FPM overhead, freeing up your backend entirely for REST API computations.
  • Framework Freedom: You can choose React, Vue, Svelte, or Astro if desired; Lila.js is the default zero-dependency solution included out of the box in frontend/js/lila.js.

2. Declarative Tagged Templates (`Lila.html`)

Templates in Lila.js use standard JavaScript tagged template literals. You can interpolate variables, conditional expressions, loops with map(), and nested templates seamlessly: 

const { html, escapeHtml } = Lila;

// 1. Basic interpolation & conditionals
const userCard = (state) => html`
    <div class="card p-4">
        <h3>${escapeHtml(state.user.name)}</h3>
        <p>Status: ${state.user.active 
            ? html`<span class="badge success">Active</span>` 
            : html`<span class="badge warning">Inactive</span>`
        }</p>
    </div>
`;

// 2. Rendering dynamic lists with map()
const productList = (state) => html`
    <div class="grid grid-cols-3 gap-4">
        ${state.products.map(item => html`
            <div class="card">
                <h4>${escapeHtml(item.title)}</h4>
                <p class="price">$${item.price.toFixed(2)}</p>
                <button data-action="addToCart" data-id="${item.id}" class="btn primary">
                    Add to Cart
                </button>
            </div>
        `)}
    </div>
`;

3. Fine-Grained Reactive State

Lila.js state is wrapped in a native Proxy. Whenever you mutate a property or modify an array (via push(), splice(), filter()), Lila.js automatically re-renders only the necessary DOM subtrees without a virtual DOM overhead: 

// Route State Declaration
Lila.route('/counter', {
    state: () => ({
        count: 0,
        history: []
    }),
    template: (state) => Lila.html`
        <div class="counter-box">
            <h2>Current Count: ${state.count}</h2>
            <button data-action="increment" class="btn primary">+1</button>
            <button data-action="decrement" class="btn secondary">-1</button>
            <ul>
                ${state.history.map(entry => Lila.html`<li>${entry}</li>`)}
            </ul>
        </div>
    `,
    actions: {
        increment: ({ state }) => {
            state.count++;
            state.history.push(`Incremented to ${state.count} at ${new Date().toLocaleTimeString()}`);
        },
        decrement: ({ state }) => {
            state.count--;
            state.history.push(`Decremented to ${state.count}`);
        }
    }
});

🌐 Global Shared Stores (`Lila.store`)

Need state shared across multiple routes (e.g. shopping cart, logged-in user profile, notifications)? Use Lila.store(): 

// 1. Create a persistent reactive store
const authStore = Lila.store('auth', {
    user: null,
    token: localStorage.getItem('token') || null,
    isLoggedIn: false
});

// 2. Mutate store anywhere; all listening components update automatically!
authStore.user = { id: 1, name: 'Alice' };
authStore.isLoggedIn = true;

4. Hash Routing, Dynamic Parameters & Guards

/users/:id (Dynamic Routes)

Route paths support parameter tokens like :id or :slug, accessible via ctx.params in actions and onMount.

Lila.beforeRoute (Auth Guard)

Intercept route transitions globally. Return false or redirect to #/login if the user lacks active session permissions.

// 1. Global Route Guard: Protect private areas
Lila.beforeRoute(async (toPath, fromPath) => {
    const isPublic = ['/login', '/register', '/'].includes(toPath);
    const token = localStorage.getItem('auth_token');

    if (!isPublic && !token) {
        Lila.toast({ title: 'Auth Required', description: 'Please log in to continue.', type: 'warning' });
        Lila.navigate('/login');
        return false; // Prevent route from rendering
    }
    return true; // Allow transition
});

// 2. Dynamic Route with onMount API Loading
Lila.route('/users/:id', {
    state: () => ({ user: null, loading: true }),
    template: (state) => Lila.html`
        <div class="profile-container">
            ${state.loading ? Lila.html`<div class="lila-skeleton"></div>` : Lila.html`
                <h1>User Profile: ${Lila.escapeHtml(state.user.name)}</h1>
                <p>Email: ${state.user.email}</p>
                <a href="/users" data-link class="btn secondary">← Back to Users</a>
            `}
        </div>
    `,
    onMount: async (state, { params }) => {
        // Fetch user from LilaPHP REST API: GET /api/users/{id}
        const res = await Lila.api.get(`/users/${params.id}`);
        state.user = res.data;
        state.loading = false;
    }
});

// 3. Start the SPA targeting your HTML outlet
Lila.start('#app');

5. Declarative Actions & Event Delegation

Never write manual addEventListener loops. Add data-action="methodName" and any optional data-* attributes to your buttons or forms. Lila.js dispatches them directly to your route's actions map: 

Lila.route('/tasks', {
    state: () => ({ tasks: [] }),
    template: (state) => Lila.html`
        <form data-action="addTask">
            <input name="title" placeholder="New task..." required />
            <button type="submit" class="btn primary">Add Task</button>
        </form>

        <ul>
            ${state.tasks.map(t => Lila.html`
                <li>
                    <span>${Lila.escapeHtml(t.title)}</span>
                    <button data-action="deleteTask" data-id="${t.id}" class="btn danger sm">Delete</button>
                </li>
            `)}
        </ul>
    `,
    actions: {
        addTask: async ({ event, state }) => {
            event.preventDefault();
            const formData = new FormData(event.target);
            const title = formData.get('title');

            // Send POST /api/tasks to backend
            const res = await Lila.api.post('/tasks', { title });
            if (res.status === 'success') {
                state.tasks.push(res.data);
                event.target.reset();
                Lila.toast({ title: 'Task Created!', type: 'success' });
            }
        },
        deleteTask: async ({ id, state }) => {
            // Confirm with built-in dialog
            const confirmed = await Lila.confirm('Are you sure you want to delete this task?');
            if (!confirmed) return;

            await Lila.api.delete(`/tasks/${id}`);
            state.tasks = state.tasks.filter(t => t.id != id);
            Lila.toast({ title: 'Task Deleted', type: 'info' });
        }
    }
});

6. Built-in API Client (`Lila.api` / `Lila.fetch`)

Lila.api is pre-configured for LilaPHP's REST backend:

  • Auto-Prefix: Requests like Lila.api.get('/users') automatically target /api/users.
  • Automatic CSRF Injection: Automatically extracts CSRF tokens from cookies or meta tags and passes X-CSRF-Token in headers.
  • JSON Handling: Auto JSON-encodes payloads and automatically parses API responses.
// GET /api/products?category=electronics
const products = await Lila.api.get('/products', { category: 'electronics' });

// POST /api/auth/login
const session = await Lila.api.post('/auth/login', { email, password });

// PUT /api/users/12
const updated = await Lila.api.put('/users/12', { name: 'Alice Smith' });

// DELETE /api/items/45
const deleted = await Lila.api.delete('/items/45');

8. Complete Production-Ready SPA Template

Copy and paste this complete boilerplate into frontend/index.html to have a fully functional reactive SPA with routing, state, dark mode, and toasts: 

<!DOCTYPE html>
<html lang="en" data-theme="dark">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>LilaPHP Single Page App</title>
    <link rel="stylesheet" href="/css/bluebird.css">
    <script src="/js/lila.js"></script>
</head>
<body>
    <header class="navbar">
        <div class="brand"><strong>⚡ LilaPHP App</strong></div>
        <nav>
            <a href="#/" data-link>Home</a>
            <a href="/users" data-link>Users</a>
        </nav>
        <button onclick="Lila.toggleTheme()" class="btn sm">🌓 Theme</button>
    </header>

    <!-- Main Application Mounting Outlet -->
    <main id="app" class="container py-8"></main>

    <script>
        const { html, route, start, api, toast } = Lila;

        // Route: Home Dashboard
        route('/', {
            state: () => ({ count: 0 }),
            template: (state) => html`
                <div class="card p-6">
                    <h1>Welcome to Lila.js 🚀</h1>
                    <p>Ultra-lightweight reactive SPA with zero build overhead.</p>
                    <div class="mt-4 flex gap-2">
                        <button data-action="clickMe" class="btn primary">Clicked: ${state.count}</button>
                        <a href="/users" data-link class="btn secondary">Manage Users →</a>
                    </div>
                </div>
            `,
            actions: {
                clickMe: ({ state }) => {
                    state.count++;
                    toast({ title: 'Clicked!', description: `Count is now ${state.count}`, type: 'success' });
                }
            }
        });

        // Route: Users CRUD
        route('/users', {
            state: () => ({ users: [], loading: true }),
            template: (state) => html`
                <div class="card p-6">
                    <div class="flex justify-between items-center mb-4">
                        <h2>Users Directory</h2>
                        <button data-action="refresh" class="btn sm">🔄 Refresh</button>
                    </div>
                    ${state.loading ? html`<div class="lila-skeleton"></div>` : html`
                        <table class="table w-full">
                            <thead>
                                <tr><th>ID</th><th>Name</th><th>Actions</th></tr>
                            </thead>
                            <tbody>
                                ${state.users.map(u => html`
                                    <tr>
                                        <td>${u.id}</td>
                                        <td>${Lila.escapeHtml(u.name)}</td>
                                        <td>
                                            <button data-action="remove" data-id="${u.id}" class="btn danger sm">Delete</button>
                                        </td>
                                    </tr>
                                `)}
                            </tbody>
                        </table>
                    `}
                </div>
            `,
            onMount: async (state) => {
                const res = await api.get('/users');
                state.users = res.data || [];
                state.loading = false;
            },
            actions: {
                refresh: async ({ state }) => {
                    state.loading = true;
                    const res = await api.get('/users');
                    state.users = res.data || [];
                    state.loading = false;
                },
                remove: async ({ id, state }) => {
                    await api.delete(`/users/${id}`);
                    state.users = state.users.filter(u => u.id != id);
                    toast({ title: 'User Removed', type: 'info' });
                }
            }
        });

        // Initialize SPA
        start('#app');
    </script>
</body>
</html>
