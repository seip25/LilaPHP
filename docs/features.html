Background Workers (`Core\Task`)

Performance First

To keep your API responses under a few milliseconds (`Performance First`), never perform heavy tasks synchronously inside request routes (like sending massive emails, resizing images, or processing CSV files). `Core\Task` automatically dispatches them to background worker processes without blocking API throughput.

How `Task::dispatch()` Works Under the Hood

`Core\Task` dynamically detects your deployment environment:

  • Distributed Redis Mode (Default in Docker Prod): If Redis (`6379`) is active in `backend/.env`, the task payload (`json`) is pushed into the `lilaphp:jobs` queue (`Redis::lPush`). Background CLI workers consume it asynchronously.
  • Standalone Fallback Mode (`proc_open`): If Redis is disabled or unavailable, `Task::dispatch()` executes a detached OS background process via `proc_open("php /path/to/_core/cli.php task:run ... > /dev/null 2>&1 &")`, instantly releasing your HTTP worker.

1. Dispatching a Task from an API Route 

use Core\Task;
use Core\Response;

// Inside backend/routes/checkout.php:
Task::dispatch('send_invoice_email', [
    'user_id' => 123,
    'invoice_id' => 'INV-2026-8891',
    'amount' => 149.99
]);

// Return JSON response immediately (in < 2ms) without waiting for the email!
Response::json(['status' => 'order_placed', 'invoice_id' => 'INV-2026-8891']);

2. Creating the Job Processor (`backend/jobs/*.php`)

When a job is processed, `Core\Task` automatically includes your PHP script from the `backend/jobs/` folder matching the job name (e.g., `backend/jobs/send_invoice_email.php` or `backend/jobs/testing.php`). Inside the script, `$jobName` and `$payload` are injected into scope: 

<?php
/**
 * Background Job: backend/jobs/send_invoice_email.php
 * Variables available in scope:
 *   @var string $jobName ('send_invoice_email')
 *   @var array  $payload (['user_id' => 123, 'amount' => 149.99, ...])
 */
use Core\Logger;

$userId = $payload['user_id'] ?? 0;
$amount = $payload['amount'] ?? 0.0;

Logger::info("Processing invoice job for User #{$userId} (${amount})...");
// Perform slow SMTP/PDF rendering work safely outside FPM request
return true;

3. Running the Worker Process (`php cli.php task:work`)

In production or high-concurrency environments, run one or more worker daemons using our `cli.php` entry point: 

# Start continuous Redis worker consuming lilaphp:jobs
php cli.php task:work

# Or run inside Docker FPM/CLI container
docker exec -it lilaphp-fpm php cli.php task:work

# To test a single job immediately without waiting for queue:
php cli.php task:run testing 'eyJwYXlsb2FkIjp7ImVtYWlsIjoidXNlckBleGFtcGxlLmNvbSIsImFjdGlvbiI6IndlbGNvbWUifX0='

4. Running Permanently in Background (`docker-compose.yml`)

To keep your background task workers and WebSocket server running continuously 24/7 in production without stopping when you close the terminal, add these permanent services inside your `docker-compose.yml`: 

services:
  # ... (existing php, nginx, mysql, redis containers) ...

  # Continuous background worker consuming Redis job queues (`lilaphp:jobs`)
  worker:
    build:
      context: .
      dockerfile: docker/php/Dockerfile.prod
    command: php cli.php task:work
    restart: always
    environment:
      - APP_ENV=production
    depends_on:
      - redis
      - mysql

  # Real-time Workerman WebSocket server daemon
  websocket:
    build:
      context: .
      dockerfile: docker/php/Dockerfile.prod
    command: php cli.php ws:serve 8001
    restart: always
    environment:
      - APP_ENV=production
    depends_on:
      - redis

Real-Time WebSockets & Redis Pub/Sub (`Core\Ws`)

New Engine

LilaPHP includes a high-performance **Socket.IO style real-time engine** powered by **Workerman (`workerman/workerman`)** and **Redis Pub/Sub**. Your PHP-FPM API routes (`POST /api/items`) can broadcast messages directly to connected frontend browsers in `< 1ms` without keeping heavy FPM worker connections open!

1. Broadcasting from PHP-FPM API Routes (`Core\Ws::publish`) 

use Core\Ws;
use Core\Response;

// Inside backend/routes/items.php (when a new item is created via POST):
Ws::publish('item_created', [
    'id' => 105,
    'name' => 'Mechanical Keyboard',
    'price' => 129.99
], 'products_room'); // Broadcast exclusively to sockets joined to 'products_room'

Response::json(['status' => 'success', 'message' => 'Item created and broadcasted live']);

2. Frontend Client Wrapper (`frontend/js/ws.js`)

Include ` ` in your HTML to use the `LilaWS` Socket.IO-style class. Packets sent while connecting are automatically queued (`sendQueue`) and flushed upon connection: 

// Connects automatically to Nginx /ws endpoint (proxied to port 8001)
const ws = new LilaWS('/ws');

// Join a specific room with optional authentication payload
ws.join('products_room', { password: 'room_password_if_needed' });

// Listen for live events broadcasted by Core\Ws::publish or clients
ws.on('item_created', (data, room) => {
    console.log(`Live notification in room [${room}]:`, data);
});

// Emit event to others in the room (excludes sender socket)
ws.emit('chat_message', { text: 'Hello others!' }, 'products_room');

// Emit event to ALL clients in the room (including the sender socket)
ws.broadcastAll('chat_message', { text: 'Hello everyone including me!' }, 'products_room');

3. Security & Room Authentication Interceptor (`backend/sockets/Handler.php`)

Intercept connections, verify room passwords/tokens before allowing join attempts, and handle custom incoming messages directly in `backend/sockets/Handler.php`: 

namespace Sockets;

class Handler
{
    // Intercept client connections (assign unique socket IDs or check headers)
    public static function onConnect(object $connection): void
    {
        $connection->socket_id = 'user_' . bin2hex(random_bytes(4));
    }

    // Intercept room join attempts (`ws.join('admin_room', { password: 'secret' })`)
    public static function onJoin(object $connection, string $room, array $payload = []): bool
    {
        if ($room === 'admin_room') {
            if (($payload['password'] ?? '') !== 'secret123') {
                $connection->send(json_encode(['event' => 'error', 'message' => 'Unauthorized access']));
                return false; // Reject join attempt
            }
        }
        return true; // Allow join
    }

    // Intercept incoming events before Workerman retransmits to the room
    public static function onMessage(object $connection, string $event, array $payload, ?string $room, object $wsWorker): bool
    {
        if ($event === 'chat_message') {
            // Persist to MySQL or sanitize input
        }
        return true; // Allow automatic broadcast to room members
    }

    public static function onClose(object $connection): void {}
}

4. Running the WebSocket Server (`php cli.php ws:serve`)

Run the WebSocket daemon on port `8001` (`/ws` proxy in Nginx) directly via `cli.php`: 

# Start WebSocket server in background daemon mode (-d)
php cli.php ws:serve 8001 -d

# Stop the running background WebSocket daemon
php cli.php ws:serve stop 8001
# Or: php cli.php ws:serve 8001 stop

# Gracefully reload/restart daemon without dropping active connections
php cli.php ws:serve restart 8001 -d

# Check live connections and worker metrics
php cli.php ws:serve status 8001

API Client & cURL Wrapper (`Core\Http`)

New helper

Need to call external microservices, payment gateways (Stripe/PayPal), or webhooks? `Core\Http` provides an ultra-lightweight cURL wrapper optimized for JSON APIs without requiring Guzzle or heavy HTTP client libraries. 

use Core\Http;
use Core\Response;

// 1. Send GET request with headers
$response = Http::get('https://api.github.com/users/seip25', [
    'User-Agent: LilaPHP-Engine/2.0',
    'Accept: application/vnd.github.v3+json'
]);

// 2. Send POST JSON request automatically
$postResult = Http::post('https://api.stripe.com/v1/charges', [
    'amount' => 2000,
    'currency' => 'usd',
    'source' => 'tok_visa'
], [
    'Authorization: Bearer sk_test_xxxxxx'
]);

// Check status codes and parse JSON response directly
if ($postResult['status'] === 200) {
    Response::json(['payment' => 'success', 'data' => $postResult['body']]);
} else {
    Response::json(['error' => 'Gateway rejected transaction'], 502);
}

Built-in Debug & Concurrency Dashboard

Real-time Suite

LilaPHP features a zero-overhead interactive Debug & Monitoring Dashboard located at /debug or /debug.html. It records live API request streams into Redis, monitors system health (Redis, MySQL, PHP-FPM, CPU/RAM/Disk), and provides an in-browser stress testing tool for concurrencies up to 4,000 requests.

Configuring Debug Environment (`backend/.env`)

Debug logging to Redis is disabled by default (DEBUG_LOGGING_ENABLED=false) to guarantee zero performance overhead. Enable it in development or staging to stream request logs: 

# Enable/disable Redis request stream logging
DEBUG_LOGGING_ENABLED=false

When deploying to production via php cli.php docker prod, if DEBUG_LOGGING_ENABLED is set to true, the CLI will display an interactive warning asking for confirmation before proceeding.

Server-Side Load Test Runner (`curl_multi`)

LilaPHP features a built-in OS-level benchmark engine powered by asynchronous curl_multi_exec sockets. Unlike browser-based tests, it executes real concurrent TCP connections and syncs live metrics to /debug.html via Redis. 

# Run 1,000 concurrent connection stress test for 30 seconds
php cli.php benchmark --url=/api/init --concurrency=1000 --duration=30
  • Req/Sec (RPS): Exact throughput measurement.
  • Latency Percentiles: Calculates P50, P95, and P99 distribution.
  • Real-Time Sync: Writes snapshots to Redis every ~500ms for web UI polling.

Running High-Concurrency Benchmark Tests (Bypassing Rate Limiters)

To run synthetic load testing at high concurrencies (100, 1000, 2000, 3000, 4000) without triggering rate limiters:

  1. Set RATE_LIMIT=0 in backend/.env (disables PHP rate limiter).
  2. Comment out Nginx C-level rate limiting in docker/nginx/nginx.conf:
# limit_req_zone $binary_remote_addr zone=api_limit:10m rate=60r/s;

location ^~ /api/ {
    # limit_req zone=api_limit burst=30 nodelay;
    # limit_req_status 429;

    include fastcgi_params;
    fastcgi_pass php:9000;
    ...
}
