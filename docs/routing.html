LilaPHP

Physical File-Based API Routing (`backend/routes/*.php`)

LilaPHP eliminates traditional routing regex loops, complex method annotations, and massive routing tables in memory. Instead, it takes inspiration from modern file-based routing systems , backed directly by Nginx FastCGI at C-level speed.

Directory to URI Mapping 
backend/routes/
├── ping.php             => GET/POST /api/ping
├── test.php             => GET/POST /api/test
├── users/
│   ├── index.php        => GET/POST /api/users
│   └── profile.php      => GET/POST /api/users/profile
└── auth/
    └── login.php        => POST /api/auth/login

When a request comes into your server (e.g., `http://localhost:8080/api/users/profile`), Nginx forwards it directly to our preloaded dispatcher (`index.php`), which locates and executes `backend/routes/users/profile.php` instantly.

API-First Endpoint Structure (`Request::GET`, `Request::POST`, etc.)

Because physical route files define the target URI in LilaPHP, request method routing is cleanly handled directly inside each endpoint script using static helpers (`Request::GET()`, `Request::POST()`, `Request::PUT()`, `Request::DELETE()`, `Request::PATCH()`). Any code before the method blocks acts as global validation or middleware for all methods in that file.

backend/routes/users/profile.php 
<?php
/**
 * API Endpoint: /api/users/profile
 */
use Core\Response;
use Core\Request;
use Models\User;

// 1. Global Validations / Middlewares (Runs for ALL HTTP methods in this file)
if (!Request::header('Authorization') && !Request::input('token')) {
    Response::error('Unauthorized request', 401);
}

// 2. GET /api/users/profile
Request::GET(function() {
    $userId = Request::input('id', 1);
    $user = User::find($userId);
    if (!$user) {
        Response::error('User not found', 404);
    }
    return ['status' => 'success', 'data' => $user];
});

// 3. POST /api/users/profile (With Middlewares)
Request::POST([AuthMiddleware::class], function() {
    $user = new User(Request::json());
    $user->assertValid(); // Emits HTTP 422 JSON response if invalid
    $user->save();

    return ['status' => 'created', 'data' => $user];
});

// 4. DELETE /api/users/profile
Request::DELETE(AuthMiddleware::class, function() {
    $user = User::find(Request::input('id'));
    $user?->delete();
    return ['status' => 'deleted'];
});

🔍 Why `Request::GET()` instead of `Route::get('/path')`?

In traditional frameworks, every HTTP request must instantiate a monolithic `$app = new App()`, parse URI string arrays, match paths with regex, and execute a central router table. In LilaPHP, Nginx maps the request URI (`/api/users/profile`) directly to the exact file on disk (`backend/routes/users/profile.php`). Because the file path is the route, calling Request::GET() or Request::POST() inside the file executes the specific verb handler with zero routing table overhead!

⚡ Key Capabilities of `Core\Request`:

  • Static HTTP Verb Handlers: Request::GET(...), Request::POST(...), Request::PUT(...), Request::DELETE(...), Request::PATCH(...).
  • Middleware Integration: Pass Closures, Class Names (e.g. AuthMiddleware::class), or arrays of middlewares directly as parameters.
  • Automatic JSON Response: Return an array or object from the route callback to emit a formatted JSON response automatically.
  • Retrieve Payload & Inputs: $body = Request::json(); or Request::input('email'); (`O(1)` memoized RAM lookup).

Nginx C-Level Rate Limiting & 404 Protection

In traditional PHP frameworks, when a bot attempts to brute-force non-existent URLs or floods the API, PHP-FPM workers must boot up, load the router, check the routes array, and eventually throw a `RouteNotFoundException`. This consumes server RAM and CPU.

Zero-PHP 404 & 429 Rate Limit Responses

In LilaPHP's Docker setup (`docker/nginx/nginx.conf`), Nginx inspects the file system and traffic rate strictly at the C-programming layer before invoking PHP:

  • C-Level 404 Handling: If an endpoint file does not exist inside `backend/routes/`, Nginx instantly returns {"error":"Endpoint not found","code":404} without waking up any PHP-FPM worker.
  • C-Level Rate Limiting: Nginx enforces rate limits (limit_req zone=api_limit rate=60r/s burst=30). If an IP exceeds the threshold, Nginx returns {"error":"Too Many Requests","code":429} directly from C memory!
