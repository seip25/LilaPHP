Micro-ORM Integration

New

LilaPHP's BaseModel provides an Active Record style ORM. Using this Micro-ORM is entirely optional — you can always fallback to standard PDO methods if you prefer raw SQL. However, using Models allows you to abstract simple queries, relate entities gracefully, and automatically validate data.

Defining Models & Schema

Models act as both a data validator (with `#[Field]`) and a schema definer. The `#[FieldDatabase]` attribute sets the table column rules. Note: these attributes are scanned by the CLI tool to automatically generate and migrate your database tables (detailed in the CLI & Migrations section below). 

/LilaPHP/models/User.php
namespace Models;

use Core\BaseModel;
use Core\FieldDatabase;
use Core\HasMany;

class User extends BaseModel {
    #[FieldDatabase(type: 'int', primaryKey: true, autoIncrement: true)]
    protected int $id;

    #[FieldDatabase(type: 'varchar', length: 255, unique: true)]
    public string $email;
    
    #[FieldDatabase(type: 'boolean', default: '1')]
    public bool $is_active = true;

    // Define relationships with modern PHP Attributes
    #[HasMany(model: Post::class, foreignKey: 'user_id', localKey: 'id')]
    public array $posts = [];
}
  /LilaPHP/models/Post.php
 
namespace Models;

use Core\BaseModel;
use Core\Field;
use Core\FieldDatabase;
use Core\BelongsTo;

class Post extends BaseModel
{
    #[FieldDatabase(type: 'int', primaryKey: true, autoIncrement: true, unsigned: true)]
    protected int $id;

    #[Field(required: true)]
    #[FieldDatabase(type: 'varchar', length: 255)]
    public string $title;

    #[Field(required: true)]
    #[FieldDatabase(type: 'text')]
    public string $content;

    #[FieldDatabase(type: 'int', unsigned: true)]
    public int $user_id;

    #[FieldDatabase(type: 'boolean', default: '1')]
    public bool $is_active = true;

    #[BelongsTo(model: User::class, foreignKey: 'user_id', ownerKey: 'id')]
    public ?User $author = null;
}

Querying & Relationships

Queries automatically exclude logically deleted records (where is_active = 0) unless overridden. You can also eagerly load relationships defined with #[HasMany], #[HasOne], or #[BelongsTo] using the `with` parameter. 

// Fetch by primary key (Automatically appends AND is_active = 1)
$user = User::find(1);

// Query with condition (Excludes logically deleted records automatically)
$activeUsers = User::where('status', '=', 'verified');

// Fetch all records (includes activeOnly filter)
$allUsers = User::all();

// You can bypass the active filter by passing activeOnly: false
$userWithDeleted = User::find(1, activeOnly: false);

// Logical Deletion Practice (Sets is_active = 0 instead of executing DELETE)
// This preserves referential integrity and audit logs securely.
$user->delete(logic: true);

// Eager Loading Relationships (Using 'with' hydrates your nested dependent models)
$userWithPosts = User::find(1, activeOnly: true, with: ['posts']);
// $userWithPosts->posts now contains an array of Post instances connected to the user

Note: When using $app->getDatabaseConnection() without parameters, it uses the database configuration defined in .env. If no configuration is found, it defaults to SQLite.
