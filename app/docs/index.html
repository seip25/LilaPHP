Why Choose LilaPHP?

LilaPHP avoids the monolithic approach of traditional frameworks. Instead of loading a massive global state, LilaPHP instantiates only what is required for the specific request. No complex setup—just run composer create-project and you're ready to go.

This means faster cold starts, lower memory usage, and the ability to run multiple "micro-apps" within the same codebase—each with different security policies, headers, or middleware configurations.

Universal compatibility: Works seamlessly on Nginx, Apache, LAMPP, XAMPP, WAMP, FrankenPHP, Swoole, VPS, shared hosting, or PHP's built-in server. Deploy anywhere without configuration headaches.

LilaPHP/routes/home.php 
include_once __DIR__ . "/../index.php";
use Core\App;

// Standard App
$app = new App(); 

// Admin Panel (Strict Security)
$adminApp = new App([
    'security' => ['cors' => false, 'sanitize' => true,'logger'=>false,'rateLimit'=>30],
     'translate'=>true
]);

// Public API (Open Access)
//rateLimit 300 request for 1 minute per IP address
$apiApp = new App([
    'security' => ['cors' => true, 'rateLimit'=>300],
    'translate'=>true
]);

Installation

Get started in under 60 seconds. LilaPHP is designed to be simple to install and easy to move between environments.

1

Install via Composer

Create a new project using the official skeleton. The project comes pre-scaffolded with all root entry points and files ready to use immediately. 

composer create-project seip25/lila-php LilaPHP
2

Initialize Environment (.env)

Enter the project directory, copy the example environment file into `app/`, and generate a secure cryptographically random key: 

# Enter project directory
cd LilaPHP

# Copy example environment configuration
cp app/.env.example app/.env

# Generate security key
php app/cli.php key:generate
3

Start Development Server

You can boot your application using Docker (recommended) or via traditional local servers (Apache, MAMP, XAMPP, LAMPP).

Option A: Docker Dev Environment

Manage container lifecycle using scripts (runs from project root) to avoid running Docker in the background when not coding: 

# Build and start containers (Nginx + PHP 8.4-FPM + MySQL)
./app/docker/dev.sh build #or sudo ./app/docker/dev.sh build

# Stop containers to free up system resources
./app/docker/dev.sh stop #or sudo ./app/docker/dev.sh stop
 
# Start existing containers without rebuilding
./app/docker/dev.sh start #or sudo ./app/docker/dev.sh start

#windows
# app\docker\dev.bat build
# app\docker\dev.bat stop
# app\docker\dev.bat start

# Run database migrations inside the container
docker exec -it lilaphp_dev_php php app/cli.php migrate:create

Visit http://localhost:8000 in your browser.

Option B: Apache / MAMP / XAMPP / LAMPP

Move the project folder into your web server root (e.g., htdocs/LilaPHP). The root .htaccess handles clean routing out of the box.

If placed in a subdirectory, modify the RewriteBase in the root .htaccess file to match your directory name: 

# .htaccess (Root Level)
RewriteBase /LilaPHP/

Visit http://localhost/LilaPHP/ in your browser.

4

Production Deployment

Deploying LilaPHP to production can be done via Apache/Shared Hosting or Docker.

Apache / Shared Hosting: Upload the directory. The app/.htaccess file denies direct web access to config/core files, while the root .htaccess safely routes extensionless requests.

Docker Prod Stack: Deploy the production Docker stack (preconfigured with OPcache, APCu, static FPM processes) using the prod lifecycle scripts from the project root: 

# Build and start optimized production containers
./app/docker/prod.sh build # or sudo ./app/docker/prod.sh build

# Stop production containers
./app/docker/prod.sh stop # or sudo ./app/docker/prod.sh stop


#Windows
# app\docker\prod.bat build
# app\docker\prod.bat stop
